00 Your own workspace

Fork it.
Make it yours.

Before changing any code, make your own copy of the class sandbox. A fork keeps the instructor's original lesson intact while giving you a safe place to experiment.

  1. 1

    Open the class sandbox

    Use the CodeSandbox link shared by your instructor. Explore the preview and source files first.

  2. 2

    Fork the project

    Select Fork in CodeSandbox, usually near the top of the editor. Sign in if asked, then wait for your personal copy to open. Check that you are working in your fork—not the instructor's original.

  3. 3

    Practice HTML in the playground

    Open playground.html and add your activity markup inside <body>. This file starts clean so you can build your own page.

  4. 4

    Link your experiment stylesheet

    To try CSS, open playground.html. Inside <head>, add a link to the empty experiments.css file:

    <link rel="stylesheet"
  href="experiments.css">
  5. 5

    Write a rule and experiment

    Add your CSS to experiments.css. Change selectors or values and compare the result in the preview.

    body {
  background-color: #f4efe6;
}

↳ Keep the instructor's original sandbox unchanged. Save all your experiments in your own fork.

01

BUILD A CLEAR OUTLINE

Headings

Use headings to organize information into a hierarchy. A heading's level shows its place in the outline—not just how large it looks.

Your challenge

  1. Add one main heading with <h1>.
  2. Add at least two section headings with <h2>.
  3. If a section needs subsections, use <h3> below its <h2>.

Check: Read only your headings. Do they make a sensible outline? Use one clear <h1> for the page's main topic.

STARTER SHAPE playground.html
<main>
  <h1>My favorite place</h1>
  <section>
    <h2>Why I like it</h2>
    <!-- Add this section's content -->
  </section>
</main>
02

WRITE AND EMPHASIZE

Paragraphs

Use <p> for a paragraph of text. Use <strong> for important words and <em> when you want to emphasize a word or phrase.

Your challenge

  1. Write two short paragraphs about your topic, each in its own <p>.
  2. Wrap one important phrase in <strong>.
  3. Use <em> to emphasize a word in the other paragraph.

Check: Each paragraph should explain one idea. The tags add meaning; CSS can change how that meaning looks.

STARTER SHAPE playground.html
<p>
  I like this place because <strong>everyone feels welcome</strong>.
</p>
<p>
  It is especially <em>peaceful</em> in the morning.
</p>
03

CONNECT PAGES AND PLACES

Links

The <a> (anchor) element makes a link. Put its destination in the href attribute and meaningful, clickable text between the opening and closing tags.

Your challenge

  1. Create a new file named about.html beside playground.html. Add a heading to that file.
  2. In playground.html, link to your new page using a relative path.
  3. Add a second link to an external website using its full address, including https://.
  4. Try changing the link text. It should clearly describe the destination.

Check: A local link uses a filename or path, like about.html. An external link uses a full URL, like https://developer.mozilla.org/.

INTERNAL: ANOTHER PROJECT PAGE playground.html
<a href="about.html">
  About this project
</a>
EXTERNAL: A WEBSITE ON THE WEB
<a href="https://developer.mozilla.org/">
  Learn more on MDN
</a>

If you put about.html inside a folder, include that folder in the path—for example, pages/about.html.

04

ADD A VISUAL

Images

The <img> element embeds an image. Its src points to the image file or URL, and its alt text describes the image for people who cannot see it.

Your challenge

  1. Upload an image to your fork, or create an images folder and add one there.
  2. Add an <img> with a local src path that matches the file's location.
  3. Try the external image example too; it uses a full web URL in src.
  4. Write concise, useful alt text. If the image is purely decorative, use alt="".

Check: A local src such as images/my-photo.jpg points into your project. A full URL loads from another site and needs an internet connection. Unlike most elements, <img> has no closing tag.

LOCAL IMAGE EXAMPLE playground.html
<img
  src="images/my-photo.jpg"
  alt="A short description of the photo">
OR TRY AN EXTERNAL IMAGE URL
<img
  src="https://placehold.co/600x400/png"
  alt="A placeholder image">
05

GROUP RELATED ITEMS

Ordered & unordered lists

Choose an unordered list when item order does not matter, and an ordered list when sequence or ranking matters. Each item goes in an <li>.

Your challenge

  1. Create a list of three favorite things with <ul>.
  2. Create step-by-step instructions with <ol>.
  3. Put each item inside <li> tags.

Check: Does changing the order affect the meaning? Pick <ol> for a sequence and <ul> for a collection.

UNORDERED: A COLLECTION
<ul>
  <li>Sketchbook</li>
  <li>Headphones</li>
  <li>Water bottle</li>
</ul>
ORDERED: A SEQUENCE
<ol>
  <li>Open the editor</li>
  <li>Write some HTML</li>
  <li>Preview the page</li>
</ol>
06

PRESENT COMPARABLE DATA

Tables

Use a table for data that belongs in rows and columns—not to position the whole page. A caption and header cells help everyone understand the data.

Your challenge

  1. Make a small table comparing three books, games, or activities.
  2. Add a <caption>, column headings with <th scope="col">, and one <tr> per row.
  3. Use <td> for data cells. Add a <thead> and <tbody> to group table parts.

Check: Keep each row's values under the correct headings. Use tables for data, not visual layout.

TABLE STRUCTURE playground.html
<table>
  <caption>My favorites</caption>
  <thead>
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Why I like it</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Example</td>
      <td>Add your reason</td>
    </tr>
  </tbody>
</table>
07

GROUP CONTENT FOR STYLING

Divs & colored boxes

A <div> is a generic block container. Use it to group elements when no more meaningful semantic element fits—then use a class to target the group with CSS.

Your challenge

  1. Wrap a heading and paragraph together inside a <div class="info-box">.
  2. In experiments.css, write a rule for .info-box that adds a background color, padding, and a border.
  3. Make a second box with the same class. Notice that one CSS rule styles both.
  4. Try the same class on a <section> or <article> to see that CSS classes can style different container elements.

Check: Choose a semantic element such as <section>, <article>, or <aside> when it describes the content's purpose. Use a <div> when a generic grouping is all you need.

HTML: GIVE THE CONTAINER A CLASS playground.html
<div class="info-box">
  <h2>Did you know?</h2>
  <p>A class name can be reused.</p>
</div>
CSS: ADD THIS TO YOUR EXPERIMENTS experiments.css
.info-box {
  background-color: #e6f0d8;
  padding: 1rem;
  border: 2px solid #789346;
  border-radius: 8px;
}

Try changing the HTML tag to <section class="info-box"> or <article class="info-box">. The class rule still applies; the element's meaning changes.

08

QUOTE A SOURCE

Blockquotes

Use <blockquote> for a longer quotation taken from another source. The optional <cite> element can name the source; it does not automatically create a citation or link.

Your challenge

  1. Choose a short quotation from a book, article, or interview.
  2. Put the quoted passage inside <blockquote>.
  3. Add the source title or author in a <cite> element nearby.

Check: Use <q> for a short quotation within a sentence, and <blockquote> for a longer, separate quotation. Provide enough source information for readers to identify it.

A LONGER QUOTATION playground.html
<figure>
  <blockquote>
    <p>It always seems impossible until it's done.</p>
  </blockquote>
  <figcaption>
    — <cite>Nelson Mandela</cite>
  </figcaption>
</figure>

This example also previews how <figure> and <figcaption> can group related content.

09

GROUP MEDIA AND CAPTIONS

Figures

<figure> groups a piece of self-contained content, often an image, with an optional <figcaption> that explains or credits it.

Your challenge

  1. Take the local image example from the Images activity and wrap it in <figure>.
  2. Add a <figcaption> with a caption or photo credit.
  3. Try a second figure containing a chart, illustration, or short code example.

Check: alt text describes the image for people who cannot see it. A caption is visible to everyone and gives context. They serve different purposes.

IMAGE WITH A CAPTION playground.html
<figure>
  <img
    src="images/my-photo.jpg"
    alt="A red kite flying above a beach">
  <figcaption>
    A windy afternoon at the beach.
  </figcaption>
</figure>
10

MAKE A MINI GLOSSARY

Description lists

A description list uses <dl> as its container, <dt> for each term, and <dd> for its description or value.

Your challenge

  1. Create a glossary of three web-development terms.
  2. Put the list inside <dl>, and mark each term with <dt>.
  3. Give each term a definition in a following <dd>.
  4. Try a list of event details, such as a date and location, instead of glossary terms.

Check: Description lists are for associated terms and descriptions (or name/value pairs), not a replacement for every bulleted list.

A WEB GLOSSARY playground.html
<dl>
  <dt>HTML</dt>
  <dd>The markup language for page structure.</dd>

  <dt>CSS</dt>
  <dd>The language used to style a page.</dd>
</dl>
11

REVEAL EXTRA INFORMATION

Details & summary

<details> creates a disclosure widget that can be opened and closed. Its first child <summary> provides the visible label. It works without JavaScript.

Your challenge

  1. Add a <details> section containing a <summary> question and a paragraph answer.
  2. Preview the page and open and close the disclosure with a mouse and keyboard.
  3. Add a second details widget about a different topic.

Check: Put the summary first inside <details>, and use a clear label that describes what will be revealed.

A NATIVE DISCLOSURE WIDGET playground.html
<details>
  <summary>What does CSS do?</summary>
  <p>CSS controls a page's presentation, such as
    colors, spacing, and layout.</p>
</details>
12

STYLE A LINK LIKE A BUTTON

Links & buttons

CSS can make an anchor look like a button, but the element still means “go to a destination.” Use <a> for navigation and <button> for an action on the current page.

Your challenge

  1. Add a link to another page and give it the class button-link.
  2. In experiments.css, add padding, a background color, a text color, and a border radius for .button-link.
  3. Add a real <button type="button"> beside it to represent an action such as “Submit Form.”
  4. Compare the two: the anchor navigates; the button represents an action. A button needs JavaScript or a form to perform that action.

Check: Do not use a link with href="#" as a fake button. Keep the correct HTML element and use CSS for appearance.

HTML: LINK FOR NAVIGATION, BUTTON FOR AN ACTION playground.html
<a class="button-link"
  href="about.html">Read About Us</a>

<button type="button">Submit Form</button>
CSS: GIVE THE LINK A BUTTON-LIKE LOOK experiments.css
.button-link {
  display: inline-block;
  padding: 0.65rem 1rem;
  color: white;
  background-color: #284b3b;
  border-radius: 4px;
  text-decoration: none;
}
13

EMBED A VIDEO

YouTube video

An <iframe> embeds another page inside yours. YouTube provides an embed URL for each video; give the frame a descriptive title so people using assistive technology know what it contains.

Your challenge

  1. Choose a YouTube video and find its video ID in the URL. For example, in https://www.youtube.com/watch?v=abc123XYZ, the ID is abc123XYZ.
  2. In playground.html, add an <iframe> using the embed URL format https://www.youtube.com/embed/VIDEO_ID.
  3. Replace VIDEO_ID with the ID for your video, and write a descriptive title.
  4. Preview the page and check that the video fits. In experiments.css, try setting the frame's width to 100% and its aspect-ratio to 16 / 9.

Check: Use YouTube's /embed/ URL, not the regular watch-page URL. Every iframe should have a descriptive title.

HTML: EMBED A YOUTUBE VIDEO playground.html
<iframe
  src="https://www.youtube.com/embed/VIDEO_ID"
              class="video-embed"
              title="A short description of the video"
  width="560"
  height="315"
  loading="lazy"
  allowfullscreen></iframe>
CSS: KEEP THE VIDEO RESPONSIVE experiments.css
.video-embed {
  width: 100%;
  max-width: 560px;
  aspect-ratio: 16 / 9;
  border: 0;
}

Add class="video-embed" to the iframe to connect it to this CSS rule.

14

PRACTICE CSS COMPOSITION

Style a card

A card is a visual group of related content. HTML provides the structure; CSS adds spacing, color, borders, and hierarchy. Build one card, then reuse its class for another.

Your challenge

  1. In playground.html, add an <article class="card"> with a heading, paragraph, and link.
  2. In experiments.css, give .card padding, a light background, a border, and rounded corners.
  3. Use max-width so the text line does not get too wide.
  4. Make a second card with the same class. Try changing the background or adding a class such as card-featured for one special card.

Check: The class name connects the HTML element to the CSS selector .card. Add the dot in CSS, but not in the HTML attribute.

HTML: STRUCTURE THE CARD playground.html
<article class="card">
  <p class="card-category">GARDEN NOTES</p>
  <h2>Grow something small</h2>
  <p>Start with one sunny pot of herbs.</p>
  <a href="about.html">Read the notes</a>
</article>
CSS: STYLE THE CARD experiments.css
.card {
  max-width: 28rem;
  padding: 1.5rem;
  background-color: #ffffff;
  border: 1px solid #dce2da;
  border-radius: 8px;
}

.card h2 {
  margin-top: 0;
  color: #284b3b;
}

Try adding box-shadow, changing the border color, or creating a reusable .card-featured class.

A QUICK DEBUGGING CHECKLIST

Common beginner mistakes

If something does not look or work as expected, check these small details first.

  • Tags are not closed or nested in the right order. Close the most recently opened element first.
  • A file name or path does not match. Check spelling, capitalization, folders, and extensions in href or src.
  • An attribute is on the wrong element. For example, links use href; images use src and should include alt.
  • A CSS rule does not apply. Check the selector, the class name (including the dot in CSS), braces, colons, semicolons, and that the stylesheet is linked.
  • Expecting a developer-tools edit to stay. DevTools changes are temporary; save lasting styles in experiments.css in your fork.

ONE LAST CHALLENGE

Create a recipe card.

Build a recipe page in playground.html, combining the elements from the activities. Use meaningful HTML first, then make the recipe feel like a card with CSS in experiments.css.

  • A recipe title with <h1>, section headings with <h2>, and an introductory paragraph.
  • A recipe photo inside <figure>, with descriptive alt text and a <figcaption>.
  • An unordered ingredients list and an ordered method list.
  • A small table for preparation time, cooking time, and servings.
  • A <blockquote> for a family cooking tip or a <details>/<summary> section for substitutions.
  • An <article class="recipe-card"> wrapper, styled with padding, background, border, and rounded corners.

Optional: add a link to a related recipe and a description list for dietary notes. Keep the page heading order logical and reuse classes when styling.
